# Ethics & Privacy Statement

## 1. Data Sources and Synthetic Data
To respect privacy and confidentiality during development and research evaluation, this platform currently operates on **Synthetic Data** generated by our simulation engine. No real-world user data, PII (Personally Identifiable Information), or production system logs were used to train the initial models or generating the performance metrics in this repository.

## 2. PII Handling & Minimization
In a production deployment, specific measures are designed to map to privacy-by-design principles:

- **No Raw PII Storage**: The ML engine processes feature vectors (numerical representations). Raw logs containing names or IPs are stored in a secure, access-controlled database with short retention policies.
- **Pseudonymization**: User IDs are hashed or tokenized in the analytical layer where possible.
- **Data Minimization**: Only metadata required for detection (timestamps, file counts, login status) is used. Content of files or emails is **not** inspected or stored by this module.

## 3. Anonymization Strategy
- **Training Data**: Real user data used for future retraining must be anonymized (names replaced with UUIDs).
- **Reporting**: Dashboards used by Level 1 analysts showing "Top Threats" can use pseudonyms (e.g., "User-A123") until a warrant or formal investigation is opened.

## 4. Compliance Alignment
This system is designed to support compliance with frameworks like GDPR and NIST 800-53:

- **Right to Explanation (GDPR)**: The "Explainability" module provides human-readable reasons for every automated alert, preventing "black box" decisions against employees.
- **Purpose Limitation**: Data collected for security monitoring is strictly used for threat detection, not for employee performance monitoring or productivity tracking.
- **Human in the Loop**: The AI provides *alerts*, not automated punishment. A human analyst must verify all incidents before any adverse action is taken.
